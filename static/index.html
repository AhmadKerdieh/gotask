persistence — phase 03 checking…

These hit the real repository layer against the real Postgres database. GET /api/v1/ready is the readiness probe (distinct from liveness): it round-trips the database. Seed creates a project + task; the slow query proves the request context aborts an in-flight query server-side.

transition tester — phase 04 idle

The service enforces workflow.yaml transitions. Seed a task above to get an id, paste it here, pick a target status, and watch a business rule accept or reject the change. Legal → updated task. Illegal → 409 invalid_transition. Unknown status → 422. A new task starts in open; try in_progress (legal) then done from open (illegal — skips the chain).
